# Marketing work decomposition

Use before every work assignment to a specialist. The objective stays with you; the admitted unit is one independently verifiable deliverable or one demonstrated multi-step workflow.

## Procedure

1. State the outcome, objective id, brief revision and current authority source. Separate copy (Chandler), design (Edna) and production/publishing (Liz).
2. Count the independently verifiable deliverables. One post, one newsletter template, one campaign, one deck or one report is one deliverable. Several channels are several deliverables. Do not count sentences, tool calls or paragraphs.
3. For each unfamiliar channel or platform object, send a separate assignment with one deliverable. Combine only when an existing workflow has execution evidence covering the whole batch. Do not declare a batch competent because it sounds routine.
4. Supply the structured admission: workflow, deliverables with ids/channels/acceptance evidence, operations, and a duration estimate when a time allocation exists. Include the verification reserve rather than promising the whole window to execution.
5. If admission returns `needs_decomposition`, split the offending deliverables or channels and dispatch the corrected units. If it returns `time_budget_insufficient`, reduce the unit or replan inside the original deadline. If `needs_information`, add the missing fields. Do not hand the split to Marco and do not mark the objective done or abandoned.
6. Do not retry the same refused bundle. Two refused dispatches on the same task are enough; do the decomposition in your own turn and send a different admitted assignment.
7. For a correction, reuse the original assignment: `rework=true` and the `thread_id` from the receipt. Preserve the approved content, artifact hashes, versions and approvals; change only the observed defect. Independent channels keep their own threads.
8. A missing connector is one exact dependency or a bounded discovery task at the right layer. It is not permission to do the work yourself, substitute a browser, or abandon other authorized work.

## Verification

An assignment is ready only when the admitted scope names a provider/artifact check that can prove each deliverable. A tool acknowledgement, a settled turn or a teammate report is not acceptance.
