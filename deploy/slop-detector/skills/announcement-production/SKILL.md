# Announcement production

Darcy owns the outcome of an announcement: which audience needs to notice it, why it matters to that audience, what supported message to convey, and what action the reader should take. Choose the creative approach within the approved campaign; do not ask Marco to supply basic marketing practice. Separate event promotion from product collateral, recruitment and evergreen editorial work.

For each channel row, record audience, objective, message, CTA/destination, exact copy version, visual treatment, copy and design owners, deadline/time zone, publication authority and evidence of completion. Match the channel and user voice; a complete sentence alone is not an effective message. A draft is not ready just because it fits a character limit or a link returns 200.

For the current launch announcements on X, Mastodon, Bluesky and Threads, include a purpose-designed event invitation image. The existing generic dashboard link preview is not an accepted substitute for event artwork. Darcy should brief Edna with the communication goal, audience, supported event facts, brand/source references, output channels, deadline and acceptance criteria. Edna decides composition and typography in Claude Design. Do not prescribe CSS, fonts or a locally recreated layout. Validate each channel's actual image requirements before selecting export sizes; do not present a guessed size as a platform requirement.

For other campaigns, decide the visual treatment explicitly according to the message and channel. Image, carousel, video or a suitable existing asset may be appropriate; document a deliberate text-only choice when it serves the brief. Do not assume every message universally requires an image, or that any decorative image solves the communication problem.

## Ownership

- Darcy: audience, positioning, brief, priorities, strategic acceptance and one consolidated report to Marco.
- Chandler: source-grounded copy, full-piece self-review and copy-preflight before handoff.
- Edna: all visual creation or modification, including social images, invitations, thumbnails, crops, compositions, typography, decks and PDFs. Use Claude Design and its native source files/features under Marco's standing instruction. Resolve Edna's existing assignment before creating a duplicate.
- Liz: schedule/dependencies, coordinating handoffs, inspecting supplied exports, factual checks, exact-copy/version preservation, channel validation and receipts. Liz does not create or alter graphics, crop or composite images, write layout/CSS/SVG, or use local image tools as a workaround. She may inspect existing files and metadata. If a visual fails review, return the specific defect to Edna within the existing assignment. A busy or blocked designer does not transfer design ownership to Liz.

Liz's review must inspect the actual final image at realistic mobile size, readable event facts and CTA where appropriate, consistent dates/time zones, safe cropping, appropriate alt text, no private data/debug overlays, correct channel format and a working destination. Check the copy and image together for contradictions and redundancy. Record the native project URL, exported version and review result. A render/export alone is not acceptance.

A release packet contains the exact reviewed copy, inspected final image(s), alt text, destination/UTMs, channel/account, proposed slot, publisher and scoped approval state. Missing design means production is incomplete; it is not a request for Marco to approve an unseen asset. Obtain the asset through Edna and complete other independent preparation. Do not publish, reschedule externally, substitute a rejected method, resume paused hire/collateral work, duplicate a human design commission or claim an approval that does not exist.

Track work in the existing calendar and Todoist task with the current owner, next action and artifact link. Report progress only after inspecting the result; a delegation, intention or checklist is not delivered work.
