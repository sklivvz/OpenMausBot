# Execute the marketing calendar
Use for Darcy's scheduled marketing runs and Liz's calendar production. Darcy owns priorities and review; Liz owns the calendar and release preparation. Keep evergreen collateral and its explicit holds separate.

## Read the actual calendar
Run `/usr/local/bin/marketing-calendar-audit` first. It is read-only, takes no arguments, inventories every row in /data/.openmausbot/workspaces/6052fe66-7cf6-4106-bdb7-1ddd816647dc/company/marketing/positron-flux-launch/publication-register.csv and highlights overdue, today, next-seven-days and undated entries. It preserves the full content and decision references. Treat its state labels as claims to verify, not completed preparation. Source failure means incomplete coverage, never an empty calendar.
Read the current shared communication calendar linked from the existing marketing task or Liz's comms-calendar records, and the latest direct user decisions. Reconcile these with the register. Do not create a competing calendar. Exact publication times and time zones come from that calendar; dates alone are not scheduled jobs. A date passing changes urgency even when no task description changed.

## Act on each upcoming row
For every overdue/today/next-seven-days row identify: stable row key, exact slot/time zone, current copy version, preparation remaining, reviewer, publisher, actual scoped approval source and next action. Include missing calendar rows in the reconciliation. Reuse open assignments. Assign independent work immediately: Chandler corrects the exact copy; Liz checks links, channel constraints, assets, audience, readiness and the calendar; Darcy reviews and prepares the decision or handoff. Run independent preparation in parallel rather than making all work wait behind one task. An unresolved release decision does not block correcting copy, reviewing it or preparing a usable posting packet.
For work assigned to Marco to post manually, deliver the exact copy, account/channel, verified link and asset before its slot. A bare approval link or an old draft buried in a document is not a ready handoff. Retrieve existing approvals before asking; a missing local approval_ref is not proof that Marco never approved. Preserve exact approved text. A strategy approval alone does not authorize arbitrary new copy or external publication. An unapproved post remains unapproved.
If the slot is at risk, finish the preparation and bring Darcy the precise missing decision with the actual packet in this run. Do not silently let the slot expire or report 'no change'. A missed slot needs a truthful status and a proposed recovery time; do not move dates or invent approval. If a ready, explicitly authorized action is blocked by a tool, attempt one available supported alternative and preserve failure evidence. Marco-only channels remain manual. Sending/publishing requires the actual scoped authority; never infer it from this repair.

## Keep the records coherent
Liz updates current fields, rather than appending contradictory histories forever; retain old evidence separately. Distinguish copy draft, internally reviewed, awaiting user decision, ready, scheduled, published, explicitly held and missed slot. Scheduling needs a platform receipt; publication needs a real post/message receipt. A publisher handoff is pending until acknowledged/executed. Compare actual results with promised dates.
After meaningful progress update the existing Todoist task with calendar row IDs, responsible actor, exact next step, deadline/time zone, deliverable link, blocker and verified comment/update receipt. Preserve user task text and original deadlines. Do not close a campaign parent because one draft is ready. Todoist is the task queue, not the complete marketing calendar.
Save a calendar execution receipt beside the register as calendar-execution.json: checkedAt, registerSha256 from the audit, sharedCalendarSource/readAt, all relevant row IDs, and per-row preparationArtifact, reviewState, approvalSource, publisher, nextAction, dueAt, assignmentId, todoistEvidence, blockerSource. Counts must reconcile with every relevant calendar row. If source access is partial, identify uncovered rows and continue independent work. A claimed all-blocked backlog requires each open task's next step and finished preparation evidence, not a four-item sample of a seventeen-task queue.
Return deliverables, verified execution and newly time-critical decisions. Quiet unchanged waiting stays in the record. Do not count bookkeeping alone as campaign execution. Keep registration/analytics checks separate from real leads; do not create synthetic registrations on the live site to test tracking.

## Copy and links
Use brand-copy-quality and the current brief. Full name Positron Flux, metric units, American spelling, international phrasing without regional colloquialisms. Feature claims follow their scoped source. Event invitations retain their required dates; collateral-specific timing exclusions do not apply to every campaign. Preserve registered UTM labels and verified destinations. Use existing approved short links where available; purchasing a tool is not a prerequisite for preparing copy. Check actual subscription, suppression and duplicate-audience state. Missing historical evidence is unknown, not a finding of no consent. Ask the person who can supply a material missing fact before changing the audience; preserve the answer and current user direction.
