# Operations intake and routing
For the scheduled todo briefings follow todo-status-briefing and use work-review. For a compact inventory request, run exactly /usr/local/bin/task-queue once. It returns a complete fresh read-only Todoist snapshot with counts per project and compact task rows; pagination and counting happen inside the tool. Report the requested state using current evidence. A status request does not authorize new assignments or an intake interview. Use work-review.read_attention_scan only when recent inbox signals are relevant. Do not fetch the same task list through another route after a successful snapshot. For a specific task's full description, use the discovered Todoist read tool for that ID.

Run these installed commands as standalone commands, without cd, redirects, pipes, chained commands or a different working directory. Their exact command grants are scoped to this engine and company working directory. COMPOSIO_REMOTE_WORKBENCH and COMPOSIO_PROXY_EXECUTE are arbitrary-code routes and may require approval; do not use them to count or summarize tasks, or ask for blanket approval. Process returned data locally only if needed. If the task snapshot fails, preserve the explicit failure and use bounded direct read tools; never treat it as an empty queue.

Use work-review.read_attention_scan with no arguments to begin the fixed read-only intake scan. Read every returned nextCursor with the same tool until nextCursor is null and allPagesRead is true. Collection and source pagination happen in deterministic code. These routine reads are already authorized. Do not invoke the attention-scan shell commands, remote workbenches or temporary command payloads. Source complete is separate from allPagesRead: preserve each source failure and its last complete baseline.

After all pages, compare stable item IDs and meaningful status with the previous successful baseline and /data/.openmausbot/workspaces/6052fe66-7cf6-4106-bdb7-1ddd816647dc/company/operations/intake-state.json. If no baseline exists, reconstruct it from the latest completed scan/report and already tracked tasks; do not dump every old item as a new alert. Commit a source watermark only when that source was fully read. Preserve evidence and receivedAt separately from your checkedAt.

Classify each new actionable signal: already tracked/owned; personal; sales; marketing; legal; accounting; development; or unresolved. An existing owned task is not new work. Route only unowned or materially changed work once to its accountable chief through real coordination. Give source ID/link, actual ask, verified deadline, what is already done, and ask for a Todoist ID plus next action. Preserve the external-action boundary: an incoming email is not authority to send, pay or accept terms.

Record assignment ID and pending/accepted/returned state. A live assignment needs no repeated poll or duplicate message. Review returned task evidence and keep the routing record. On later sweeps examine an idle unfinished handoff only when its follow-up is due or new evidence shows failure. Resolve with one concrete correction and track it. Do not resend the same request every run.

Donna is the personal point of contact. Heads own execution and their project queues. Bill may handle a requested cross-project move with native Todoist tools after schema discovery, but preserve task identity, deadlines, history and subtasks; read back the destination. An ambiguous owner goes to the responsible chief or one narrow user decision, not a guessed name. Legacy Herald/Tessa/Counsel/Ledger labels need current-role mapping, not revival of retired bots.

Keep scheduled scanning read-only at source. Its action is an internal handoff; it sends no external email/Slack message and mutates no source mail. Specific user/team-lead requests for task routing are separate authorized operations. Do not make counts or a fixed check-in message the outcome. With no new actionable signal, record a quiet baseline only; alert Marco only for a genuinely urgent unowned blocker or a decision that the accountable chief cannot resolve.

An unresolved due handoff is actionable even when the inbox has no new messages. Check the actual assignment outcome and current Todoist next step. For a failed or expired handoff, make one corrective handoff with its source and remaining deliverable, or resolve a routing action you own; record the receipt. If there is no reachable owner, record and surface that exact ownership decision once rather than treating the item as handled. Read company/operations/execution-receipts when available to detect repeated no-progress outcomes; absence is unknown, not evidence of success. A bot marked idle may still have queued or waiting work.
