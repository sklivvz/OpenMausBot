# Marketing outcome brief

Use for every new marketing objective, correction or specialist assignment. Darcy keeps the business outcome; the brief is the handoff, not a substitute for it.

## 1. Recover the actual request

Read the latest direct user message, the current task brief, existing decisions and approved artifacts. Separate what the user approved from what a teammate recommended. Preserve explicit stops and the current version. Do not reopen settled decisions or invent a missing approval.

Record: outcome, audience, purpose, exact deliverable, approved source and version, authorised operations, exclusions, time allocation and acceptance evidence. If no deadline exists, choose a realistic internal target without inventing a user deadline.

## 2. Check capability before promising

Name the exact installed connector, MCP tool or artifact workflow the executor will use. Inspect the tools actually exposed in this thread; a similar past thread, a skill name or a browser route remembered from earlier is not current capability. Check the target account and permission too.

If a granted connector exists, require it. Never assign the browser for Google Docs, Sheets, Slides or Drive, or for any workflow with a functioning connector, even after a permission error. A missing connector or denied scope is a blocker, not permission to bypass. Only for a genuine connector gap, such as TinyURL, may a scoped authorised assignment use the managed Docker browser with its actual tools and saved login. Bluesky remains connector-only; the existing deny means no browser. Record one exact gap if neither route exists: capability, account, operation, observed response and owner. Do not hide it under a generic channel name, assign an impossible job or retry the same request.

## 3. Decompose by verifiable deliverable

One independently verifiable deliverable or one demonstrated workflow per assignment. One post, one newsletter template, one calendar change, one report or one saved link is one deliverable. Several channels are several deliverables. Combine only when execution evidence already covers the whole batch.

Separate copy (Chandler), design (Edna) and production/publishing (Liz). Independent channels and objectives get separate assignment threads. A correction reuses the original assignment with rework=true and the original thread_id; preserve approved content outside the defect scope.

## 4. Supply the structured admission

Before Liz work, provide the fields the runtime validates:

- objectiveId and briefRevision
- workflow: single-channel, newsletter-platform-production, artifact-production, research or multi-channel
- deliverables: id, channel when the workflow uses one, exact account for publish, acceptance
- operations: research, review, prepare, assemble, install_template, configure_campaign, publish, verify
- estimatedDurationMs and verificationReserveMs when a time allocation exists

Use `check_marketing_brief` for the brief's mechanical consistency. It does not grant authority or prove suitability. If admission returns needs_decomposition, needs_information or time_budget_insufficient, correct the assignment in this turn. Do not retry the same refused bundle; two refusals mean stop and decompose.

## 5. Define acceptance

Name the exact provider readback, artifact or signed receipt that will prove the deliverable. For publication: provider object ID/permalink, account and content hash. For preparation/assembly: saved artifact path/hash and a signed receipt when the operation requires one. A turn, report, tool acknowledgement, sourceComplete flag or teammate claim is not acceptance. Unknown stays unknown.

## 6. Review and close honestly

Read the returned artifact or provider state yourself before accepting it. Return observed defects to the responsible owner on the same thread. Stop when the acceptance check passes. Keep the parent objective open until its own conditions are met. A blocked deliverable does not close or abandon the objective.

## Verification

An assignment is ready only when the executor's actual capability, one deliverable, exact operations, time reserve and acceptance evidence agree. The brief is coherent when another person could execute it without guessing and Darcy can verify the result independently.
