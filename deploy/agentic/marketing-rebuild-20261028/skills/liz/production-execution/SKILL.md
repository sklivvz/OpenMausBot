# Production execution

Use for one admitted channel, newsletter or production deliverable. The admitted scope is the limit; extra work needs another assignment.

## 1. Confirm the assignment and capability

Read the admitted scope, current brief, exact copy version, media and alt text, target account, authorised operations and acceptance evidence. Inspect the tools actually exposed in this thread. Name the exact connector or artifact workflow you will use.

Connector-first is absolute. If a granted connector or MCP exists for the operation, use it. Never use the browser for Google Docs, Sheets, Slides or Drive, or for any workflow with a functioning granted connector, even if the connector returns a permission error or the browser looks easier. A missing connector, denied scope or provider error is not permission to bypass with the browser; it is one exact blocker. The managed Docker browser is allowed only for a genuine connector gap, such as TinyURL, under a scoped authorised task. In that case inspect the actual mounted browser tools, use the existing saved-login mechanism, record the exact browser steps and readback, and do not substitute shell/curl, a local layout, rewritten copy, a new account, an old link or an anonymous API route. Google Workspace is connector-only; do not attempt it through the browser even if reachable. Bluesky is connector-only and the existing tool deny remains; no browser bypass. If the browser route is also unavailable, return one blocker with capability, account, operation, exact response and next owner. Continue other independent items already admitted. A new missing skill is a bounded discovery task with lead support, not an automatic refusal.

## 2. Execute once and reconcile

For an external write, execute once. Before any retry, or after an ambiguous response, reconcile the existing provider object or operation identity. Never repeat blindly or change IDs to bypass `unknown`, `processing`, a stale lock or a mismatch.

Read back the actual provider state with a separate read or reconcile call: exact ID, URN or permalink, account, content hash, media ID and status. Save the provider response as a task artifact. A publish acknowledgement, a flag, a report or a settled turn is not acceptance.

## 3. Record deterministic evidence

The execution-tools host exposes read-only queue/context tools and a signed receipt. Use exact inputs:

- `read_execution_queue`: optional projectId, or a cursor. Returns snapshotId, rows and nextCursor. Read every page before relying on its coverage.
- `read_execution_context`: requires snapshotId from a queue read, taskId, threadId and optional expectedTaskSha256; or a cursor. A threadId/taskId alone is not a valid call.
- `record_execution_receipt`: use the validated schema. operationId, botId, taskId (current work thread id), objectiveId, projectId (the Marketing department id, `dept_*`, not a Positron task project field), sourceVersion (current brief revision), nextStep, and 1-8 evidence references. Persist the actual task and department scope.

Evidence references are exact:

```
{"kind":"artifact","id":"...","path":"/absolute/path/inside/an/artifact/root"}
{"kind":"assignment","id":"...","threadId":"...","rootId":"..."}
```

Use the validated schema rather than a remembered workaround. A first artifact receipt establishes only a baseline; its outcome is unverified. For an owned local artifact, observe the absent or old state before the write, then record the current bytes after it; or use actual `assembled-output` verification. Never fabricate a baseline, alter approved content, or manufacture a byte change just to satisfy the progress gate. A receipt records observed artifact or assignment state, not publication. For a published object the provider readback above is the acceptance evidence. A missing receipt makes the result unverified; it does not prove the work was absent. Preserve the exact report and do not repeat the outward action.

If a receipt tool fails, preserve the exact error and return the blocker as unverified. Do not claim success from a hand-written hash, a sourceComplete flag or a teammate report.

## 4. Stay inside the role

Do not add a channel, deliverable or operation, even under time pressure. Do not author or rewrite copy, create or alter design, layouts, CSS, SVG, graphics, crops or composites, or edit protected originals. You may inspect, assemble, install and verify supplied copy and design exactly. Browser fallback is only for a genuine connector gap under scoped authorisation; never Google Workspace, never where a granted connector exists, and never for copy/design work. Do not use Gmail; the user refused that grant for Liz.

## 5. Corrections and time

Corrections stay on the original assignment thread: use `rework=true` and the original thread_id, change only the observed defect, and preserve approved content, versions and approvals. Respect the current time allocation. Do not start an operation that cannot finish inside the remaining window; reserve integration and verification time. Only a new explicit person allocation extends it.

## Verification

A valid return names the exact provider or artifact object and its evidence, or one exact blocker. A receipt is not a publication. A tool acknowledgement, a report or a settled turn is not completion.
